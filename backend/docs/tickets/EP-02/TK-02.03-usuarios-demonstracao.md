## O que entregar

Na banca, o apresentador abre a tela de entrada e escolhe com quem entrar (colaborador, massoterapeuta, RH ou suporte), sem copiar IDs do terminal. Um usuário criado ou desativado pelo RH aparece ou some da lista na hora.

- `GET /auth/demo-users`, `@Public()`. Só com `AUTH_MODE=header`; em outro modo responde 404, como rota inexistente.
- Lista de usuários **ativos**, agrupada por papel na ordem `EMPLOYEE`, `THERAPIST`, `HR`, `ADMIN` e, dentro de cada papel, por nome em ordem alfabética pt-BR.
- Cada item: `id`, `name`, `firstName`, `role`, `roleLabel` ("Colaborador", "Massoterapeuta", "RH", "Suporte") e `spokenText` ("{nome}, {papel por extenso}."). Sem e-mail, `googleSubject` nem datas.
- `roleLabel`, papel por extenso e `spokenText` vêm do catálogo de mensagens. `firstName` usa a mesma função pura do TK-02.02 (quem entrar primeiro cria).
- Leitura do banco a cada chamada, sem cache.
- Acrescentar a linha `GET /auth/demo-users` ao teste da matriz de permissões.
- `CONTEXT.md`, seção "Decisões tomadas": acrescentar a D-12.

Fora deste ticket: a tela do frontend (TK-09.02), sessão no backend, qualquer forma de senha ou login.

## Critérios de aceite

- [x] **Dado** `AUTH_MODE=header` e usuários ativos de todos os papéis, **quando** se chama `GET /auth/demo-users` sem identificação, **então** responde 200 com a lista na ordem `EMPLOYEE`, `THERAPIST`, `HR`, `ADMIN` e, dentro de cada papel, em ordem alfabética.
- [x] **Dado** um usuário inativo, **quando** a lista é pedida, **então** ele não aparece.
- [x] **Dado** a lista, **quando** se inspeciona qualquer item, **então** há `id`, `name`, `firstName`, `role`, `roleLabel` e `spokenText`, e não há e-mail.
- [x] **Dado** um item da lista, **quando** se lê o `spokenText`, **então** ele começa pelo nome e termina com o papel por extenso, em uma frase.
- [x] **Dado** `AUTH_MODE=google`, **quando** se chama `GET /auth/demo-users`, **então** responde 404.
- [x] **Dado** um usuário criado depois da primeira chamada, **quando** a lista é pedida de novo, **então** ele aparece.
- [x] **Dado** o seed de demonstração executado, **quando** a lista é pedida, **então** traz os sete usuários de demonstração com os papéis certos.
- [x] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.

## Testes esperados

- **Seam 1, e2e:** com `createTestApp()`, usuários criados no teste: ordem, filtro de ativos, campos sem e-mail, `spokenText`, usuário criado entre duas chamadas; linha nova na matriz de permissões.
- Modo Google: `createTestApp()` ganha a opção de sobrescrever a configuração (`AUTH_MODE=google`), do mesmo jeito que já aceita outro `Clock`; o teste confere o 404 sem chamar o Google.
