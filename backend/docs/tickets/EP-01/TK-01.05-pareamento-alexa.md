## O que entregar

O banco passa a guardar qual Alexa pertence a qual massoterapeuta e os códigos de pareamento que o RH vai gerar. Ele garante que um aparelho não se repete e que um código só é usado uma vez, mesmo com dois aparelhos tentando ao mesmo tempo.

- `alexa_devices`: ID, `device_id` da Amazon (único), massoterapeuta (FK) e data do pareamento. Um massoterapeuta pode ter vários aparelhos; um aparelho pertence a um só.
- `alexa_pairing_codes`: ID, código, massoterapeuta (FK), quem gerou (FK para `users`), `expires_at`, `consumed_at` (nulo até ser usado) e aparelho que o usou (FK para `alexa_devices`, nulo até ser usado).
- Índice único parcial no código entre os não usados.
- Nada além do `device_id` sobre o aparelho; nenhum dado da conta Amazon.
- Modelo Prisma `AlexaDevice` e o do código, com nomes do glossário.

Fora deste ticket: formato e validade do código, "um código ativo por massoterapeuta" (TK-03.08), troca de dono ao parear de novo e intent de vínculo (TK-07.05), substituição do mapa fixo da variável de ambiente.

## Critérios de aceite

- [x] **Dado** um `device_id` já pareado, **quando** se grava outro aparelho com o mesmo `device_id`, **então** o banco recusa.
- [x] **Dado** um massoterapeuta com um aparelho pareado, **quando** se pareia um segundo aparelho a ele, **então** o banco aceita.
- [x] **Dado** um código ainda não usado, **quando** se grava outro código não usado com o mesmo valor, **então** o banco recusa.
- [x] **Dado** um código já usado, **quando** se grava um código novo com o mesmo valor, **então** o banco aceita.
- [x] **Dado** um código não usado e dentro da validade, **quando** duas atualizações condicionais tentam consumi-lo ao mesmo tempo, **então** só uma afeta o registro.
- [x] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.
