## O que entregar

O RH vê e cadastra salas e troca o token do QR Code quando ele vaza ou é impresso errado:

- Módulo `rooms/` com `GET /rooms` (filtros `locationCode` e `active`; ordem alfabética), `POST /rooms` e `POST /rooms/:id/regenerate-token`, todas `@Roles("HR")`. Formatos da spec.
- O token novo invalida o anterior na hora: o check-in com ele falha com `invalidCheckIn`.
- Auditoria: `ROOM_CREATED` e `ROOM_TOKEN_REGENERATED`, sem o valor do token.
- Remover `GET /admin/locations` e `POST /admin/rooms`.
- Linhas novas na matriz de permissões.

Fora deste ticket: cadastro de unidades, imagem do QR Code (frontend).

## Critérios de aceite

- [x] **Dado** a Sala 1 com o token `T1`, **quando** o RH chama `POST /rooms/:id/regenerate-token`, **então** a sala recebe um token `T2` e o check-in com `T1` é rejeitado com erro de token inválido, enquanto o check-in com `T2` funciona.
- [x] **Dado** o evento de auditoria da regeneração, **quando** consultado, **então** não contém `T1` nem `T2`.
- [x] **Dado** uma unidade existente, **quando** o RH cria uma sala, **então** responde 201 com um token gerado e há um `AuditEvent` de criação.
- [x] **Dado** um nome de sala já usado na mesma unidade, **quando** o RH cria outra com ele, **então** responde 409.
- [x] **Dado** salas nas duas unidades, **quando** o RH chama `GET /rooms?locationCode=LONDRINA`, **então** só vêm as de Londrina, em ordem alfabética.
- [x] **Dado** um colaborador ou massoterapeuta, **quando** chama essas rotas, **então** responde 403 (matriz de permissões).
- [x] `npm run test`, `npm run test:e2e`, `npm run lint` e `npm run build` passam.

## Comentários

- **2026-10-21 — alinhado à spec da Mariana.** Este ticket foi reescrito depois do merge para seguir as rotas da spec. Propostas da primeira versão que **não estão na spec**, a decidir com a Mariana:
  - Renomear sala.
  - Desativar sala, recusando quando ela tem períodos de agenda futuros, para não deixar período em sala inativa. A spec não diz como uma sala fica `active = false`.
  - Gerar o token por fonte criptográfica (a spec diz "novo UUID": `randomUUID` do Node atende).
- **2026-10-21 — implementação.** Decisões a confirmar com a Mariana:
  - `updatedAt` da regeneração é o instante do `Clock` no momento da troca. A tabela `rooms` não tem `updated_at` e a spec não prevê migração, então o valor não é gravado nem aparece em `GET /rooms`.
  - Com a remoção de `GET /admin/locations`, nenhuma rota lista as unidades, mas `POST /rooms` pede o `locationId`. O TK-12.02 vai precisar de um `GET /locations` (ou do `locationId` em `GET /rooms`, que já vem em cada sala).
  - `POST /rooms` com unidade inexistente responde 404 `locationNotFound`; `POST /rooms/:id/regenerate-token` com sala inexistente responde 404 `roomNotFound`. O nome repetido responde 409 `roomNameAlreadyExists`, comparando o nome sem espaços nas pontas.
